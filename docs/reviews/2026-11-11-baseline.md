## Findings

### CR-001 · P1 · Content, Accessibility, SEO · M — The CV PDF publishes private details, is indexable, untagged, titled "Europass", dated in its name and older than the page
**Where** docs/CV-Europass-202509-Atzeni-EN.pdf; index.html:111-114
**Rule** Privacy (product decision); WCAG PDF9/PDF16/PDF18 (tagged, language, title); Google indexes PDF text and titles results from PDF metadata; stable URLs
**What** The page shows only city and email, but its first-screen download serves the Europass PDF whose page 1 carries the home address, the phone number and the date of birth; it is live, committed to the public repo, and indexable (Pages cannot send `X-Robots-Tag`). `pdfinfo`: `Title: Europass`, `Tagged: no`, no `/Lang`. The file name carries `202509`, so the next CV either keeps a stale name or breaks shared links. It is also weaker than the page (RustNES "a partial port", RuScheme "[Current]" though last pushed 2023, no graybox/tracker/munote) and has typos ("Wndows", "IPTV e VoIP", "Ci/CD").
**Change** A decision for the user: (a) keep it deliberately; (b) publish a new PDF without the private details, tagged, titled "Pietro Atzeni — CV", under a stable name (`docs/Pietro-Atzeni-CV.pdf`) — either re-exported from Europass, or generated from the site's own print stylesheet (headless Chrome, tagged) — and remove the old file (it stays in git history unless the history is rewritten); (c) drop the download and offer the CV on request.
**Decision** fix now — download removed and PDF deleted; purge from history at the next push (user: remove the download; purge it)

### CR-002 · P1 · Rendering, Accessibility · S — Below 352 px the nav clips "Education"; the nav's overflow clips every link's focus ring
**Where** style.css:300-301, 337-349, 115-119 · agent-D/320-light-top.png, agent-F/focus-nav-*.png
**Rule** Nav reachable at 320 px; WCAG 1.4.10 Reflow, 2.4.7 Focus Visible
**What** At 320 px the five links need ~312 px in ~280 px: "Education" shows as "Educ", the scrollbar is hidden, nothing hints at a sideways scroll (every width ≤ 351 px). Because the list is a scroll container with `.25rem` vertical and no side padding, the 3 px-offset focus ring is clipped to 1 px top and bottom, and loses its outer side on the first and last links.
**Change** `@media (max-width: 351px) { :root { --header-h: 5.25rem } .site-nav ul { flex-wrap: wrap; justify-content: center; gap: 0 1.1rem } }`, and give the list room for the ring: `.site-nav ul { padding: .4rem .35rem; margin-inline: -.35rem }`.
**Decision** fix now

### CR-003 · P1 · Accessibility · S — Nav text drops to 4.26:1 when dark thumbnails scroll under the translucent header (light)
**Where** style.css:285-288, 358
**Rule** WCAG 1.4.3 Contrast (Minimum)
**What** The header is `--bg` at 86% over a blurred backdrop. Over the RustNES/graybox/RuScheme thumbnails it composites to #dad8d6, and `--text-muted` nav text measures 4.26:1 (verified by pixel sampling behind the glyphs: all five links at 375 px, three or more at 768, "About" at 1440). Dark theme passes.
**Change** Make the header opaque: delete `background: color-mix(in srgb, var(--bg) 86%, transparent)` (the `var(--bg)` line above it then wins, 5.7:1), and drop the now-pointless `backdrop-filter`.
```css
285  background: var(--bg);
286  background: color-mix(in srgb, var(--bg) 86%, transparent);
288  backdrop-filter: saturate(140%) blur(10px);
```
**Decision** fix now
